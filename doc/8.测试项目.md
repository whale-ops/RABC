# 8. 测试项目

## 8.1 测试目标与数据

证明功能正确且不会跨租户、越角色、越数据范围。以下为计划和验收要求，不表示测试已执行或通过。

测试数据采用合成数据：租户 A/B；A 下总部、研发及研发子部门、财务；用户为租户管理员、只读审计、项目查看 ALL + 编辑 SELF、多 CUSTOM 部门、无角色、无部门、停用用户。每租户均建立同名 username，验证租户内唯一、跨租户可重复。

## 8.2 分层测试

| 层级 | 工具建议 | 关键覆盖 |
| --- | --- | --- |
| 领域单测 | JUnit 5 | 权限并集、按操作合并数据范围、树循环、可授予集合 |
| 服务集成 | Spring Boot Test + Testcontainers | 真实 MySQL/Redis、事务、复合外键、版本冲突 |
| API 契约 | MockMvc / OpenAPI 校验 | HTTP 状态、DTO 校验、字符串 ID、字段脱敏 |
| 前端单测 | Vitest | 路由注册、权限刷新、single-flight、关键表单 |
| 端到端 | Playwright | 登录到授权生效、退出、权限撤销、文件下载 |
| 性能 | k6 或 JMeter | 分页、授权缓存、日志、并发刷新、批量写入 |

不使用 H2 替代 MySQL 验证生成列、复合唯一索引与 SQL 数据范围。测试日志不得输出真实 token 和密码。

## 8.3 核心验收用例

| 编号 | 操作/场景 | 预期 |
| --- | --- | --- |
| AUTH-01 | 正确/错误密码登录 | 正确返回会话；错误信息不区分账号是否存在 |
| AUTH-02 | accessToken 过期，连续 10 请求 | 页面内只发起一次刷新，业务请求各重试最多一次 |
| AUTH-03 | 复用已轮换刷新 token | 拒绝并撤销 family，产生安全事件 |
| AUTH-04 | 跨站提交 refresh/logout | 缺 CSRF 或非法 Origin 返回 403 |
| AUTH-05 | 修改密码后使用旧会话 | 全部旧会话失效，要求重登 |
| AUTH-06 | 首次登录未改密调用业务 API | 正常返回业务数据；可在个人中心修改密码，改密后旧会话失效 |
| TEN-01 | A 用户猜测 B 用户/项目 ID | 详情/修改/删除返回 404，无旁路数据 |
| TEN-02 | A 新增用户绑定 B 角色/部门/岗位 | 拒绝，数据库无部分关联 |
| TEN-03 | 请求体篡改 tenantId/createdBy | 拒绝敏感字段，无法跨租户落库 |
| TEN-04 | 同用户名跨租户创建 | 可成功，同租户重复 409 |
| TEN-05 | 租户停用/到期仍带有效令牌请求 | 会话拒绝，不等待 token 自然到期 |
| RBAC-01 | UI 无按钮，直接调用对应 API | 403 |
| RBAC-02 | 授予本人未拥有或不可委派权限 | 403，原角色权限保持不变 |
| RBAC-03 | 普通管理员分配内置管理员角色 | 拒绝 |
| RBAC-04 | 撤销权限后继续调用已打开页面 API | 5 秒内拒绝，发布异常期间受栅栏保护 |
| RBAC-05 | 角色停用后使用原 token | 对应授权立即进入撤销流程 |
| DATA-01 | 查看 ALL 角色 + 编辑 SELF 角色 | 全部可读，仅本人可改 |
| DATA-02 | 无部门使用 DEPT / 空 CUSTOM | 返回空范围，不能退化成全量 |
| DATA-03 | CUSTOM 两个部门，不含其子部门 | 只出现两个指定部门的数据 |
| DATA-04 | 详情、统计、导出和批量删除 | 与同操作的数据范围一致，批量越权全部回滚 |
| DATA-05 | 部门移动后查看子部门范围 | 闭包与缓存同步生效，无旧树越权 |
| USER-01 | 删除最后一个租户管理员 | 409 或业务拒绝，租户仍可管理 |
| USER-02 | 同账号连续软删/重建两次 | 唯一键不冲突，有效账号仍唯一 |
| CON-01 | 两客户端按相同 version 修改 | 一个成功，另一个 409 |
| CON-02 | 相同幂等 key 不同请求体 | 409，不创建第二条业务记录 |
| FILE-01 | 伪造扩展名/路径穿越/超大文件 | 拒绝，无工作目录外写入 |
| FILE-02 | A 下载 B 文件或无权业务附件 | 404，不返回对象地址 |
| FILE-03 | 文件扫描未通过/有关联时删除 | 禁止下载/删除，符合状态规则 |
| AUDIT-01 | 改角色、重置密码及失败写入 | 成功审计可靠落地，失败不被事务回滚吞掉 |
| AUDIT-02 | 检查请求/异常/下载日志 | 无密码、token、Cookie、未脱敏敏感字段 |
| DASH-01 | 无用户统计或安全监控权限 | 对应指标为 null，不能旁路获取聚合值 |
| DASH-02 | 项目分布与总数/空数据 | 同范围一致，空数据无伪造统计 |

## 8.4 故障与恢复测试

- Redis 不可用：受保护 API 返回 503，不放行、不产生刷新风暴。
- 权限事务提交后缓存同步失败：栅栏继续拒绝，outbox 恢复后版本一致。
- MySQL 不可用：readiness 失败，写请求明确失败，不误报成功。
- 审计投递中断：关键事件保留在 outbox，恢复投递不重复污染展示。
- 上传中断/对象存储超时：无可下载脏文件，孤立对象可定期清理。
- 数据库备份恢复后：两租户边界、权限、附件引用与迁移版本正常。
- 多标签页同一刷新 Cookie：协调后只轮换一次；失败不会循环重试。

## 8.5 性能验收建议

目标待在预生产实测确认：2 个应用实例，每实例 4 vCPU/8 GiB；数据库 4 vCPU/16 GiB；Redis 2 vCPU/4 GiB；测试 100 租户、10 万用户、100 万项目、1000 万日志。

在 100 并发、持续 30 分钟、以读 80%/写 20% 为样例负载下：核心列表/详情 P95 ≤500ms、普通写入 P95 ≤800ms、5xx <0.1%。文件传输/异步导出另测，不混入普通 API 延迟口径。预热、索引、网络和数据范围分布都需记录。

如不满足，先检查慢 SQL、tenant/data_scope 索引、N+1、连接池及缓存命中，不以关闭权限检查换取指标。覆盖率用于发现盲区，授权决策分支和高风险用例必须覆盖。

## 8.6 建议检查命令与门禁

工程建立后执行后端 `mvnw.cmd verify`；前端 `pnpm lint`、`pnpm typecheck`、`pnpm test:unit`、`pnpm build`、`pnpm test:e2e`。需在项目中先建立相应脚本和集成测试 profile，本文命令当前不可视为已可运行。

P0 上线要求 P0 功能及全部适用安全用例通过；P1 上线增加文件/自定义数据范围/指标用例。安全阻断问题为零、迁移与恢复演练通过、无生产 mock/默认密码、Java 17 构建通过。交付报告包含 commit、环境、数据规模、通过/失败/未测清单、缺陷和证据。
