# 1. 开发环境搭建

## 1.1 技术基线

| 层级 | 选型 | 说明 |
| --- | --- | --- |
| Java | **JDK 17** | 编译、测试、容器运行时统一；禁止使用 Java 21 API |
| 服务端 | Spring Boot 3.5.x / Spring Security | Boot BOM 管理 Spring 组件，补丁版本初始化时锁定 |
| 构建 | Maven 3.9.x + Maven Wrapper | `maven.compiler.release=17`，统一 UTF-8 |
| 持久化 | MyBatis-Plus + MySQL 8.4 | 显式租户和数据权限过滤，迁移使用 Flyway |
| 缓存 | Redis 7.x | 会话、限流、授权缓存；业务主数据以数据库为准 |
| 前端 | Vue 3 + TypeScript + Vite | Vue Router、Pinia、Element Plus、ECharts、Axios |
| 前端运行时 | Node.js 24.12+，限定 24.x | 初始化时验证 Vite 等工具兼容性，再锁定具体补丁 |
| 包管理 | pnpm | 在 packageManager 字段固定版本，提交 pnpm-lock.yaml |
| 文档与测试 | OpenAPI 3、JUnit 5、Testcontainers、Vitest、Playwright | 前后端契约与真实数据库验证 |
| 交付 | Docker Compose、Nginx | 本地环境及首版单机/双实例部署 |

MyBatis-Plus、Flyway、springdoc 等独立组件需进行兼容性验证后集中锁定，不能使用动态 `latest`。Flyway 根据所选版本配置 MySQL 支持模块。依赖版本不是本设计稿中的已验证构建产物。

## 1.2 目标目录

当前仓库只有原型及文档。下面的目录、命令是后续实施约定，需在创建对应工程后执行。

```text
VibeCoding/
├─ doc/
├─ 原型图设计.png
├─ star-admin-server/
│  ├─ pom.xml
│  ├─ mvnw / mvnw.cmd
│  ├─ star-common/          # 通用模型、异常、校验，无业务依赖
│  ├─ star-security/        # 会话、鉴权、权限上下文
│  ├─ star-system/          # 租户、用户、角色、组织、菜单
│  ├─ star-file/            # 文件存储与附件关联
│  ├─ star-audit/           # 操作、登录审计
│  ├─ star-business/        # 示例项目，验证数据权限
│  └─ star-admin/           # 启动、配置、模块组装、Flyway migrations
├─ star-admin-web/
│  ├─ src/{api,components,layouts,router,stores,views,directives,types}
│  └─ pnpm-lock.yaml
├─ deploy/{compose,nginx,scripts}/
└─ .env.example            # 仅变量名和非敏感示例
```

依赖方向：业务模块依赖 common/security 的公共接口；admin 负责组装，不允许公共模块反向依赖业务模块。审计通过事件接口接入，避免循环依赖。

## 1.3 环境与端口

| 服务 | 本地端口 | 本地说明 |
| --- | --- | --- |
| Vue 开发服务 | 5173 | `/api` 代理到后端，浏览器同源访问 |
| 后端 API | 8080 | 基础路径 `/api/v1` |
| MySQL | 3306 | 库 `star_admin`，utf8mb4，数据库会话时区 UTC |
| Redis | 6379 | 独立开发实例，禁止将生产缓存映射本地 |
| 文件存储 | 后端存储适配器 | 开发可用工作目录内文件夹，生产使用私有对象存储 |

先检查 `java -version`、`mvn -version`、`node --version`、`pnpm --version`、`docker version`。IDE Project SDK、Maven Runner JDK、JAVA_HOME 均指向 17。引入 Maven Enforcer 校验 Java `[17,18)`，CI 同样使用 17。

## 1.4 配置约定

```dotenv
SPRING_PROFILES_ACTIVE=local
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=star_admin
DB_USERNAME=star_app
DB_PASSWORD=<从本地未提交配置注入>
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=<从本地未提交配置注入>
APP_PUBLIC_ORIGIN=http://localhost:5173
FILE_STORAGE_MODE=local
FILE_STORAGE_ROOT=./var/uploads
```

`.env` 不会自动被 Spring Boot 读取；后续启动脚本或 Compose 必须将变量注入进程。前端 `VITE_API_BASE=/api/v1`，所有 `VITE_` 变量视为公开信息，不得放密码或令牌。

环境拆分 `local/test/staging/prod`；数据库、缓存、文件桶相互独立。开发 Cookie 允许本地 HTTP，生产必须 Secure。数据库应用账号仅有 DML 权限，迁移账号由部署流程单独持有。

## 1.5 工程建立后的启动顺序

```powershell
# 在项目根目录；compose 文件实现后可用
docker compose --env-file .env -f deploy/compose/compose.local.yml up -d

# 在 star-admin-server；完成初始迁移及模块创建后可用
.\mvnw.cmd -pl star-admin -am spring-boot:run

# 在 star-admin-web
pnpm install --frozen-lockfile
pnpm dev
```

多模块 `spring-boot:run` 的插件仅绑定到启动模块；若构建配置无法跳过库模块，则先 `mvnw install -DskipTests`，再进入 star-admin 执行启动目标。首次生成锁文件使用普通 `pnpm install`，后续统一 frozen-lockfile。

## 1.6 环境验收

- Java 17 编译成功，数据库迁移成功，Redis 连接正常。
- `/actuator/health/liveness` 就绪前也可独立反映进程存活；readiness 检查必要依赖。
- 前端可打开登录页，API 代理生效，错误响应带 traceId。
- 首次管理员通过一次性初始化流程建立，不提交固定默认密码。
- 重启后用户数据保留；清理开发容器前确认是否会删除数据卷。
