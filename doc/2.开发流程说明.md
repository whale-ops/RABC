# 2. 开发流程说明

## 2.1 目标与角色

交付一个可二次开发的企业管理后台：统一身份、权限、组织、审计、文件、配置和运维入口。首版采用模块化单体，不引入微服务拆分及分布式事务。

| 角色 | 职责及边界 |
| --- | --- |
| 平台管理员 | 创建/停用租户，执行首次租户管理员初始化；不浏览租户业务数据 |
| 租户管理员 | 管理本租户组织和授权，授权范围不能超过本人可授予权限 |
| 业务管理员 | 依据角色使用项目等业务模块，受数据范围约束 |
| 普通用户 | 使用已授权页面和操作，查看/编辑本人允许的数据 |
| 审计人员 | 持只读日志权限，敏感字段脱敏，无修改审计记录能力 |

租户管理员为系统内置角色；首版限制其由平台初始化、不得由普通授权流程创建或分配。至少保留一个启用的租户管理员，管理员不能通过删除自己导致租户失管。

## 2.2 原型转需求

| 原型区域 | 需求 | 优先级 |
| --- | --- | --- |
| 顶栏 | 折叠菜单、面包屑、已授权路由搜索、全屏、个人资料、退出 | P0；通知 P2 |
| 欢迎横幅 | 当前用户昵称、平台能力说明 | P0 |
| 四个统计卡 | 用户总数、项目总数、系统运行时间、安全事件 | 用户 P0，其余按实际能力开放 |
| 访问趋势 | 7/30/90 天访问量，统一时区和聚合规则 | P1 |
| 业务分布 | 业务项目类型计数，合计与项目总数一致 | P1 |
| 快捷操作 | 新增用户、角色、菜单、上传文件、日志、系统设置 | 按模块阶段和权限显示 |
| 最近操作/动态 | 本租户内、本人可见审计范围的数据 | 操作 P0，动态 P1 |
| 左侧导航 | 系统、业务、数据、日志、文件、监控模块 | 按后端菜单树生成 |

## 2.3 迭代与交付

| 里程碑 | 工作内容 | 完成条件 |
| --- | --- | --- |
| M0 工程底座 | Java 17、多模块、Vue 工程、CI、迁移、统一响应 | 干净环境可构建、启动、迁移 |
| M1 身份与组织 | 租户、登录/刷新/退出、用户、角色、菜单、部门、岗位 | 两租户独立登录；接口拒绝越权 |
| M2 P0 交付 | 基础数据过滤、首页用户统计、审计、权限失效机制 | P0 用例全部通过，无演示数据误入生产 |
| M3 P1 交付 | 文件、字典、参数、完整数据范围、项目示例、首页趋势、监控 | 数据范围、文件隔离、指标口径验收 |
| M4 上线 | 压测、恢复演练、安全检查、运行手册 | 预生产验收及回滚演练通过 |

## 2.4 单个功能流程

1. 明确用户故事、租户边界、权限码、字段及异常路径。
2. 更新数据库迁移方案和 API 契约，确定前后端共同模型。
3. 后端完成实体、DTO、服务、权限及数据过滤；前端可按已批准契约 mock。
4. 完成页面、权限交互和表单校验，移除该功能的 mock 开关。
5. 联调正常流程，以及无权限、跨租户、并发修改、会话过期等反例。
6. 提交 PR，说明行为变化、迁移影响、验证证据和回滚方式。
7. 合并前通过自动检查；部署后观察错误率和权限拒绝异常。

## 2.5 协作规范

- 分支建议 `feat/user-management`、`fix/tenant-isolation`；主分支始终可构建。
- 每个变更聚焦一项需求，不顺带批量升级依赖或修改无关文件。
- OpenAPI、数据库迁移、权限种子、前端路由应在同一需求中配套提交。
- 数据库变更追加版本脚本，已执行脚本不重写。
- PR 至少覆盖越权反例和迁移影响；涉及授权、文件下载、租户拦截时重点人工评审。

## 2.6 Definition of Done

- 功能按权限码注册；页面、按钮、接口、服务层语义一致。
- 新租户业务表包含 tenant_id，查询/写入/导出均有隔离证明。
- 参数服务端校验，日志脱敏，无固定生产凭据。
- 涉及写操作有操作审计，关键授权操作有同步审计记录。
- Java 17 构建、类型检查、相关单测及集成测试通过。
- 页面具备加载、空数据、失败、无权限状态；文档随契约更新。
