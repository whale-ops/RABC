## 4. 核心约定

- 架构：模块化单体、前后端分离，优先完成可部署、可审计的基础平台。
- 租户模式：共享数据库、共享表，以 `tenant_id` 隔离；用户属于单个租户。同一自然人跨租户使用不同账号记录，首版不做登录后切租户。
- 授权模型：用户 → 角色 → 菜单/按钮权限；后端接口和服务校验权限，前端控制可见性。
- 平台管理员管理租户生命周期，不天然拥有租户业务数据权限；租户管理员只能在本租户内授权。
- 所有 ID 使用 BIGINT，API 中输出十进制字符串；时间按 UTC 存储，API 使用 ISO 8601，界面按 Asia/Shanghai 展示。
- 会话使用随机不透明令牌 + Redis；访问令牌放前端内存，刷新令牌放 HttpOnly Cookie。详细规则见第 5、7 篇。
- 原型中的 1,248、86、32 天等均为视觉演示值，不作为初始生产数据。

先阅读本文确定范围，然后按 1 → 2 → 5 → 7 → 6 → 8 → 9 实施；使用 AI 辅助开发前阅读第 3 篇。API 字段以第 5 篇为准，表约束以 backend/src/main/resources/db/schema.sql 为准，权限语义以第 7 篇为准。变更这些契约时同步更新相关文档。
