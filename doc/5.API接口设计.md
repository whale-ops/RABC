# 5. API 接口设计

## 5.1 通用契约

- 基础地址 `/api/v1`，JSON UTF-8，字段使用 lowerCamelCase。
- ID 均为字符串；时间例如 `2026-10-18T13:00:00.000Z`。日期范围按半开区间 `[from,to)`。
- 分页 `page=1&size=20`，size 最大 100；排序如 `sort=createdAt,desc`，字段必须映射后端白名单。
- GET 不产生业务变更；POST 创建，PUT 全量替换指定配置，PATCH 修改指定字段，DELETE 删除。
- 除登录、刷新、CSRF 初始化与探针白名单外，默认要求认证；业务接口继续检查权限和数据范围。
- 对外 DTO 禁止接受 tenantId、createdBy、passwordHash；未知安全敏感字段直接拒绝。

```json
{
  "code": "OK",
  "message": "成功",
  "data": {
    "records": [{"id": "1001", "username": "zhangsan", "version": 0}],
    "total": 1,
    "page": 1,
    "size": 20
  },
  "traceId": "7e2c13b8a4014e55"
}
```

普通成功 HTTP 200，创建 201，删除成功 204 且不带 JSON；文件内容下载返回二进制。失败返回相同 envelope，data 可为字段错误数组，不能暴露堆栈、SQL 和敏感凭据。

| HTTP | code 示例 | 场景 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 字段/枚举/分页不合法 |
| 401 | AUTH_REQUIRED / SESSION_EXPIRED | 未登录或会话失效 |
| 403 | PERMISSION_DENIED / TENANT_DISABLED / CSRF_INVALID | 功能无权、当前租户不可用、CSRF 失败 |
| 404 | RESOURCE_NOT_FOUND | 不存在或不在当前数据可见范围 |
| 409 | DUPLICATE_KEY / VERSION_CONFLICT / RESOURCE_IN_USE | 唯一冲突、并发修改、仍被引用 |
| 413 / 415 | FILE_TOO_LARGE / UNSUPPORTED_MEDIA_TYPE | 上传大小/类型不符 |
| 429 | RATE_LIMITED | 登录/接口限流，带 Retry-After |
| 500 / 503 | INTERNAL_ERROR / SERVICE_UNAVAILABLE | 未处理异常或必要依赖不可用 |

## 5.2 登录与会话

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /auth/csrf | 初始化绑定浏览器预会话的 CSRF token，no-store |
| POST | /auth/login | tenantCode、username、password；失败统一描述 |
| POST | /auth/refresh | 读取刷新 Cookie 并轮换，需 CSRF token |
| POST | /auth/logout | 撤销当前会话，清理 Cookie；已失效可幂等返回 204 |
| GET | /auth/me | 当前用户、tenant、roleCodes、permissions、authVersion |
| GET | /auth/menus | 当前用户可见菜单树及 routeName/componentKey |
| PATCH | /auth/password | oldPassword、newPassword；成功撤销全部会话并要求重新登录 |

登录前先请求 csrf，提交登录/刷新/退出均带 `X-CSRF-Token` 并校验 Origin。csrf token 由服务端与预会话或刷新会话绑定，登录后重新签发；Cookie 采用 HttpOnly（刷新令牌）、SameSite=Lax，生产 Secure，Path 限定 `/api/v1/auth`。纯 Bearer 业务接口不接受 Cookie 认证。具体 TTL、并发刷新规则见第 7 篇。

```json
// POST /auth/login
{"tenantCode":"demo","username":"admin","password":"<用户输入>"}
// HTTP 200 的 data
{"accessToken":"<opaque-token>","tokenType":"Bearer","expiresIn":900,"mustChangePassword":false}
```

浏览器只将 accessToken 放内存；刷新 Cookie 不返回 JSON。登录、刷新响应 `Cache-Control: no-store`。初始密码标记仅用于个人中心的建议提示，不拦截菜单或业务接口，也不自动跳转改密页。密码修改后所有旧会话失效。

登录页账号申请采用管理员人工核实方式，无邮件验证码：

- `POST /auth/register`：提交租户、账号、姓名、邮箱、手机号与密码；通过 CSRF 和密码策略校验并持久化后返回 202，`data` 包含真实 `requestId/status/message`。租户无效返回 400，账号已存在返回 409；重复待审核申请返回原编号。只创建待审核申请，不直接授权或启用用户，密码保存为 BCrypt 摘要。
- `POST /auth/forgot-password`：提交租户、账号、已绑定邮箱与手机号。公开响应统一返回 202，匹配的账号才生成找回申请；不会自动修改密码或发送邮件。两类申请共同限制每个来源 IP 每分钟 5 次。
- `GET /system/account-requests?page=1&size=10&status=pending`：租户管理员且有 `system:user:list` 权限可查看本租户的待处理、已通过、已拒绝申请；不返回密码摘要。
- `POST /system/account-requests/{id}/review`：提交 `decision`（approve/reject）和必填的身份核实说明 `note`。通过注册还需 `deptId`、普通 `roleIds`，沿用新增用户与分配角色权限；通过找回还需 `newPassword`，沿用重置密码权限与范围校验。处理与账号变更在同一事务内，处理后清除摘要并记录审计。禁止重复处理和跨租户处理；内置管理员不支持在此重置。

## 5.3 系统管理

用户删除：单条 `DELETE /system/users/{id}?version=...` 与批量 `POST /system/users/batch-delete` 物理删除选中账号及个人资料、角色/岗位绑定、本租户按 user_id 或账号匹配的注册与找回密码申请。其他用户及角色保留；旧会话失效。内置管理员、当前账号受保护，任意失败整批回滚，审计保留历史 ID。角色删除仅删除所选角色、解除该角色的用户绑定并清除菜单/部门配置，不删除任何用户账号。

角色导入沿用上述批量事务规则：`GET /system/roles/import/template` 下载 EasyExcel 模板；`POST /system/roles/import/preview` 上传 `.xlsx` 并返回 `matrix`；`POST /system/roles/import` 接收 `{rows:[RoleWrite...]}`。三类接口均要求租户管理员和 `system:role:create`。预览不写库，每批最多 100 条、文件最大 1 MB；导入新增普通角色，不写成员、菜单授权和自定义部门关联。角色名称与编码必须唯一，失败返回数据序号并回滚整批。前端模板默认数据范围为“仅本人”、状态为“启用”；自定义部门范围需导入后通过权限设置配置。

Excel：`GET /system/{resource}/export` 使用 EasyExcel 返回 `.xlsx`，沿用资源原有导出权限及数据范围。`GET /system/users/import/template` 下载 Excel 模板；`POST /system/users/import/preview` 以 multipart 的 `file` 字段上传 `.xlsx`，仅返回首个工作表的 `matrix` 供预览（最多 1 MB、100 行）。`POST /system/users/import` 接收 `{rows:[UserWrite...]}`，在同一事务中新增全部用户，任一行失败全部回滚；导入和预览仅允许租户管理员且有新增用户权限。模板默认部门和角色由前端补全到各行，服务端再次校验关联和角色授权。ID 与手机号以文本写入 Excel，不包含密码摘要。

表中路径均相对基础地址。详情、更新、删除都先检查租户和数据范围。

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| GET/POST | /system/users | system:user:list / create | 分页/新增 |
| GET/PATCH/DELETE | /system/users/{id} | system:user:read / update / delete | 详情/编辑/软删 |
| PATCH | /system/users/{id}/status | system:user:update | status、version |
| PUT | /system/users/{id}/roles | system:user:assign-role | roleIds 全量替换、version |
| POST | /system/users/{id}/password-reset | system:user:reset-password | 一次性临时密码，建议在个人中心改密并撤销旧会话 |
| GET/POST | /system/roles | system:role:list / create | 角色列表/新增 |
| GET/PATCH/DELETE | /system/roles/{id} | system:role:read / update / delete | 角色详情/维护 |
| GET/PUT | /system/roles/{id}/permissions | system:role:read / grant | menuIds 全量替换、version |
| GET/PUT | /system/roles/{id}/data-scope | system:role:read / scope | scope、deptIds、version |
| GET | /system/menus/tree | system:menu:list | 管理用菜单树，区别于 auth/menus |
| POST | /system/menus | system:menu:create | 新增菜单/按钮 |
| PATCH/DELETE | /system/menus/{id} | system:menu:update / delete | 修改/删除，父节点约束 |
| GET | /system/depts/tree | system:dept:list | 部门树 |
| POST | /system/depts | system:dept:create | 新增部门 |
| PATCH/DELETE | /system/depts/{id} | system:dept:update / delete | 编辑/删除 |
| GET/POST | /system/posts | system:post:list / create | 岗位列表/新增 |
| PATCH/DELETE | /system/posts/{id} | system:post:update / delete | 岗位维护 |
| GET/POST | /system/dict-types | system:dict:list / create | P1 字典类型 |
| PATCH/DELETE | /system/dict-types/{id} | system:dict:update / delete | 字典类型维护 |
| GET/POST | /system/dict-types/{id}/items | system:dict:list / create | 字典项 |
| PATCH/DELETE | /system/dict-items/{id} | system:dict:update / delete | 字典项维护 |
| GET | /system/configs | system:config:list | 配置列表，敏感值不返回 |
| PATCH | /system/configs/{id} | system:config:update | 仅白名单可编辑参数 |

上表 `/` 分隔的短权限码继承前缀，例如 `system:user:list / create` 即 `system:user:list`、`system:user:create`。不把表中的简写直接存入数据库。

新增用户输入：username(3–64)、nickname(1–64)、deptId、postIds、roleIds、email、phone、initialPassword；用户名允许小写字母、数字、下划线，初始密码遵循平台密码策略，可在个人中心修改密码。更新不允许改 username；角色授权使用专用端点。详情不返回密码哈希，手机号邮箱按权限脱敏。编辑请求必须含 version，更新影响行数为 0 时返回 409。

授权目标用户/角色、所有 menuIds、deptIds、roleIds 都先检查属于本租户且有效；授权内容不得超出操作者的“可授予集合”。内置管理员角色不能通过普通角色接口增删改或授予。

## 5.4 首页与业务示例

| 方法 | 路径 | 权限码 | 返回数据 |
| --- | --- | --- | --- |
| GET | /dashboard/overview | dashboard:read | userTotal、projectTotal、uptimeSeconds、securityEventTotal、asOf |
| GET | /dashboard/visits?days=7 | dashboard:read | days 仅 7/30/90，date/count 序列 |
| GET | /dashboard/business-distribution | dashboard:read | typeCode、label、count |
| GET | /dashboard/activities?limit=5 | dashboard:read | 过滤可见审计事件后的动态 |
| GET/POST | /business/projects | business:project:list / create | 项目分页/新增 |
| GET/PATCH/DELETE | /business/projects/{id} | business:project:read / update / delete | 项目详情/维护 |

首页权限不隐含用户、项目、安全日志权限。未授权某统计指标时字段返回 null，并附 `availableMetrics`；不返回无权查看的聚合数据。最近操作表直接调用审计列表接口，仍需 audit:operation:list。

用户总数=本租户当前有效未删除用户；项目总数=当前用户在项目读取权限与数据范围内可见的未删除项目；安全事件=本租户最近 24 小时高危/严重事件，需 monitor:security:read。运行时间为当前服务实例启动秒数，多实例标明实例标识并需 monitor:read。

访问量=通过鉴权的页面访问事件次数，按租户及 Asia/Shanghai 自然日聚合，剔除静态资源和健康探针，不称独立访客数；需单独实现可信事件采集。分布与项目总数使用相同可见范围，scope 非 ALL 时不使用全租户汇总缓存。同比为相同长度上一周期，基期 0 时 ratio=null；运行时间和安全事件不展示“上升即利好”的箭头。

## 5.5 文件、日志、监控与平台

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| POST | /files | file:upload | multipart file，默认上限 20 MiB，返回文件元数据 |
| GET | /files | file:list | 本租户且在文件可见范围内分页 |
| GET | /files/{id}/content | file:download | 租户、所有权或业务附件可读权限校验后下载 |
| DELETE | /files/{id} | file:delete | 有附件引用则 409，清理对象可异步重试 |
| POST | /attachments | file:attach | fileId、bizType、bizId；校验文件使用权及业务写权限 |
| GET | /attachments?bizType=&bizId= | file:download | 同时校验业务读取权限 |
| DELETE | /attachments/{id} | file:attach | 同时校验业务写权限，只解除关系 |
| GET | /audit/operations | audit:operation:list | 分页、时间、操作者、类型、结果过滤 |
| GET | /audit/logins | audit:login:list | 登录日志 |
| GET | /monitor/summary | monitor:read | 脱敏运行指标，无连接串/密码 |
| GET/DELETE | /monitor/sessions/{id} | monitor:session:read / revoke | 会话详情/强制下线；P1 |
| GET | /monitor/sessions | monitor:session:read | 当前租户在线会话分页 |
| GET/POST | /platform/tenants | platform:tenant:list / create | 仅平台域身份 |
| PATCH | /platform/tenants/{id} | platform:tenant:update | 租户信息/状态；停用撤销会话 |

租户新建时返回一次性管理员激活流程引用，不能返回持久明文密码。平台会话与租户会话独立校验，租户管理员不能调用 platform 接口。

平台认证入口为 `/platform/auth/csrf`、`/platform/auth/login`、`/platform/auth/refresh`、`/platform/auth/logout`、`/platform/auth/me`，方法与租户同类入口一致；平台登录不接收 tenantCode，只查询 platform_user。使用独立 Cookie 名和 `/api/v1/platform/auth` 路径，复用相同 CSRF、轮换与失效策略；平台业务端点仅接受平台 Bearer 会话。首版平台身份由运维初始化，不提供公开注册。

## 5.6 并发、幂等与契约交付

- 用户编辑、角色授权、数据范围、配置修改采用 version 乐观锁；同一角色授权更新在事务内锁角色并递增版本。
- 创建项目/文件关联等可重试写入支持 `Idempotency-Key`，作用域为租户+用户+端点+key，保留 24h；请求体哈希不一致返回 409。
- 单纯限时 Redis 锁不能保证业务幂等；幂等记录与业务写入同事务落库，并保存结果引用。
- 批量写操作必须有明确上限，先校验全部资源；默认全成功或全回滚。
- 后续实现生成 OpenAPI schema；每项接口补齐字段长度、必填、示例、权限、状态码及安全方案，以契约测试验证实现。
